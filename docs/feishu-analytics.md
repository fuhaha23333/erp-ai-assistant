# 飞书自然语言数据分析

飞书群问数与网页共用独立云端语义接口、条件校验、分域计划转换、Pandas/Decimal计算和口径解释。销售、已完成销售退货、已确认销售出库、备份时点库存均可执行，须加载包含相应事实的新快照。使用现有应用机器人、授权群及独立助手库；启动命令仍是 `scripts/start_feishu_bot.py --sales`，无需新增飞书权限或建表。

## 提问示例

网页和飞书一起使用时，在项目根目录执行`uv run python start.py`即可同时启动，按`Ctrl+C`一起停止。单独启动机器人仍使用`uv run python scripts/start_feishu_bot.py --sales`；不要同时运行统一入口和另一份机器人实例。

在已授权群中 @机器人，用自己的话描述想了解的情况。可以先说一个宽泛目标，再根据引导补充；以下只是示例，不是固定问法清单：

- `分析2026年9月1日至5号的销售数据，哪些药品卖的好`
- `统计2026年9月1日至7日销售概览`
- `2026年9月1日至7日每日销售趋势，并列出商品销售额前5名`
- `2026年9月1日至7日客户订单数排行前10名`
- `比较2026年9月8日至14日与2026年9月1日至7日的销售额，按商品拆解变化贡献`
- `2026年9月1日至7日日波动线索`

日期须在快照完整范围内，可发送 `数据范围` 查询。相对日期以飞书消息发送日期、Asia/Shanghai 为准，不使用处理日期或备份日期替代。实际完整日期取决于当前部署加载的快照，未接入实时同步；本地最新数据版本见项目进度。

品种同比／环比缺数时，机器人使用“所选日期暂无完整数据”卡片，首屏复述已理解的对象、指标、本期、上期及去年同期，并列明缺少完整数据的期间。日期已明确时不再用“确认一下你的想法”表示缺数，也不把这类问题当成自然语言未理解。最多建议三个所需比较期均已覆盖的完整月份；选月份只修改本期日期，保留指标、品种／客户筛选及比较方向，编号选择不再调用模型。任意其他日期仍可直接用文字提出。

例如明确查询2026年10月的品种出库金额、同时比较上期和去年同期，当前备份只能支持完整日期至2026年9月23日：卡片应保留本期10月、上期9月、去年10月，说明本期与上期未完整覆盖，而不是自动改查8月。原始记录覆盖范围与可完成同比／环比的本期范围不同。

“卖得好／卖的好／畅销”默认销售金额前10名，显式订单数、前N名优先。“药品”按用户确认的当前商品范围处理，回复标注未按药品类别筛选。指定药名可通过本地对象匹配筛选；仅药品、排除器械等类别条件、销售件数、利润等尚不能执行，不会悄悄丢掉条件。退货和销售出库数量按单位分别统计；库存数量只代表当前快照标明的备份时点，可明确选择该时点后查询，不能当今天的实时库存。

## 商品和客户筛选

可以指定商品、客户名称或编码，也可以追加排除条件。销售、退货、销售出库支持商品与客户组合筛选；库存仅支持商品。具体对象与“仅药品”等类别条件不同，类别筛选仍未接入。

名称同名或不完整时，机器人显示本地授权数据中的候选名称和编码，保留日期、指标及其他筛选。再次@机器人选择编号（以当前用户最新提问卡片为准），或用文字提供完整编码；不需要重新描述整个问题。确认后的对象在后续追问中保留，改变包含／排除关系也保留已经确认的同一对象。候选选择复用既有签名动作和按用户隔离的上下文。

金额只统计匹配明细，单据数去重；未找到对象时请核对名称，不会自动查询全部或显示虚构零值。完整规则见[对象筛选说明](analysis-assistant.md#指定商品客户与排除条件)。

## 追问

收到分析结果或引导后，30分钟内在同一群再次 @机器人，可用自己的话补充或修改。**连续分析会话最多5轮，首次提问算第1轮，结果后的追问也计入**，卡片显示当前轮次。例如：

- `换成按订单数排，取前5名`
- `取前3名`
- `再看客户排行`
- `清除追问上下文` 或 `重新开始`

第5轮仍正常分析：可执行时返回结果；仍需补充时显示“本次对话已结束”，保留本次已理解需求和未解决事项供参考，不再邀请第6轮补充或展示可选编号。下一条完整问题从第1轮开始，不继承旧条件；回复旧编号只提示重新提问，不执行旧选择。可随时发送“重新开始”提前清除上下文。

计数随助手任务决策保存，机器人重启、同一任务恢复或消息去重不增加轮次；仅成功送达的有效分析结果／引导建立下一轮记忆。帮助、数据范围、连接测试、重新开始不占分析轮次，模型失败／超时不建立新记忆。升级前无轮次的有效历史记录按第1轮兼容，历史任务不批量改写。该上限仅作用于飞书，网页对话不变。

上下文按应用、租户、群、用户隔离，仅继承已成功送达的结构化计划或澄清状态。例如“这几天卖了多少钱”收到日期提示后，再@机器人回复“三天”。有效期按追问入队时刻判断，排队延迟不改变语义。快照变更或上下文过期后需重新指定日期；多目标不能明确继承时要求澄清。清除请求按入队顺序形成屏障，不依赖清除提示是否先送达。机器人重启不丢失尚有效的上下文；`unknown`或`rejected`送达不能建立上下文。

引导卡片优先显示一句追问与编号选项，通常2至3项；业务域完全不明确且四域可用时展示销售、退货、出库、库存四项。大模型根据本次表达识别歧义，程序校验候选并提供当前可行的建议，不维护客户问法清单。明确的筛选、数量口径或未接入业务仍保留；需要移除条件、换指标、改日期或只保留可分离的销售目标时，由用户明确选择。没有可安全绑定的候选时只问具体问题，不编造选项。

飞书追问使用卡片2.0；首屏突出问题、选项和“再次@我回复编号；都不是，也可以直接用文字说明”。已理解的需求、默认条件、完整待确认事项与30分钟有效期收进“查看已保留的条件与说明”折叠区，避免每轮重复展开长篇说明。日期覆盖和库存非实时限制仍直接可见，同名候选保留名称及编码，移除条件等动作保留完整含义。每次补充仍需在同一群再次@机器人。发送“帮助”或“数据范围”时，根据当前快照和授权分别展示四域是否可查及对应日期。

建议以编号显示，并明确标注“以最新一张提问卡片为准”。同一应用、租户、群、用户范围内，编号绑定最近语义任务中成功送达且仍在30分钟窗口内的提问卡片；更早的卡片即使未回答也不阻挡选择。新问题尚未完成、最近卡片送达不确定、已清除或过期时，不会回退套用旧卡片。选择直接应用已绑定动作，不再调用模型，支持连续选择方向、日期和同名对象，并保留已回答轮次记录。网页日期选择器不出现在飞书卡片中，也不占用语义候选名额，仍可用文字日期补充。提问卡继续使用编号，结果卡另有比较切换及客户贡献按钮；不从被引用卡片定位旧编号，旧卡内容需用文字明确说明。

## 回复内容

自然语言负责选择分析目标，结构化结果类型决定固定布局。卡片按“日期与范围 → 关键数字 → 图表／分页明细 → 折叠说明”组织；支持六类结果及组合分析，无需为不同问法设计排版。

| 分析 | 默认展示 |
|---|---|
| 销售概览 | 销售金额、订单、采购企业和商品指标，平均每单金额 |
| 商品／采购企业排行 | 前5项横向条形图，完整请求结果的分页表格 |
| 每日趋势 | 完整日期序列折线图，分页明细 |
| 期间比较 | 本期、比较期、差额、变化率和贡献明细 |
| 波动线索 | 规则说明、当日／前日金额及变化率表格 |

分析结果使用飞书卡片2.0，要求客户端7.20及以上；更早客户端仅显示标题和升级提示。原生图表使用本地计算结果生成VChart定义，不嵌入网页Plotly。模型不生成卡片代码。未知展示模板使用通用字段表格，空数据有明确提示。正常补充、能力缺口和日期缺口使用普通蓝色说明卡片，展示已知条件、单个问题及建议；模型、网络等失败仍使用错误提示。模型产生的文字、条件和建议标签按纯文本展示，不解析为提及或Markdown指令。

旧分析表格每页5行，单卡最多5个表格和2个图表；第6个明细使用折叠精简列表。统计口径、分析说明默认折叠，药品范围说明保持可见。卡片同时限制28KB和200个元素：五个经营主题优先保留图表、减少展开明细行数，极端组合再退回核心列表；旧模板先移除可选图表再减少明细。节选明确显示行数，缩短日期或减少排名条数可重新查询。截短趋势时移除图表，避免误认为覆盖完整区间。

金额概览以Decimal格式化为千分位两位小数，五个经营主题的明细保留原始精度，完整计算及留存金额仍为四位；超大数值不转为不可靠的绘图坐标。名称及编码作为纯文本处理，同名对象的图表序号独立。日期、范围、来源、规则版本与查询编号保留，订单依据ID保存在完整结果及文本回退中。比较结果保留其余维度贡献；规则波动不声称因果。完整报告外链须待可访问且有鉴权的部署地址就绪后接入，当前不生成本机链接。

### 五个经营主题的详细展示

飞书与网页使用同一计算结果；五个经营主题按“关键指标、原生图表、展开明细”展示，手机无需横向拖动六列表格。首个比较基准使用两列指标，其他基准使用紧凑摘要；点击“完整概览与比较期间”和“逐项详细数据”可查看全部汇总及原始精度，编码、规格、厂家与单位均保留。环比标注上期，同比标注去年同期，并列出对应日期；不把节选榜单重新相加当作全局汇总。金额图及大额指标使用元／万元，图表点击可放大；绘图浮点坐标不替代Decimal原值。

| 主题 | 卡片展示 |
|---|---|
| 品种增长 | 本期／上期或去年同期金额（或分单位数量）、净变化、增长／下降贡献、榜外贡献；逐项变化率、日均、数量、贡献占比及可比性 |
| 价格变化 | 全部品种的涨跌／持平／不可比计数；各品种两期均价、价差、变化率、数量、客户数、单位采购成本与单位毛利空间，不跨品种汇总均价 |
| 销量与毛利 | 两期收入、采购成本、毛利和毛利率，销量增但毛利未增的组数；逐项销量、售价、成本影响及舍入调整，非正基数与不可拆解说明 |
| 库存积压 | 库存时点、销售观察期、占用金额及成本缺失、分单位库存量和各风险计数；批次库龄、入库／到期日、近期出库、日均、累计售完估算、风险与资料缺口 |
| 旺季备货 | 目标期、库存时点、去年同期与近期日期；各规格历史数量、折算参考需求、库存及效期可覆盖／不足／未知构成 |

图表按主题生成：增长按比较基准和数量单位分别展示增减前5项，并把完整汇总中未绘制的贡献计入“其余增长／下降”；价格比较同一品种规格的两期售价、单位成本和毛利空间，缺失成本不填零；毛利展示选定品种销量、售价、成本影响和舍入调整；库存以条形图展示可重叠的风险计数，不使用占比饼图；备货比较同一规格单位的同期参考需求、近期速度对照与效期合格库存。每卡最多2图，未绘制的其他基准或品种有明确提示，详情保留。

备货在途、到货日、供货周期与目标需求仍在网页填写后计算缺口和最晚下单日；卡片不伪造尚未填写的情景结果。资金收益继续暂缓。网页证据弹窗、完整下载和手填情景不属于本次卡片按钮。

### 结果卡按钮

增长、价格、毛利结果可展开“继续分析 · 切换比较／客户贡献”，点击只看环比、只看同比、同时比较，或选择最多3个品种规格查看客户贡献。组合结果仅节选部分主题按钮；其余品种和主题仍可文字追问。点击在本地重算并回复新卡，不调用模型，也不修改群内原卡。比较切换保留其他分析目标、日期和筛选；客户下钻限定选中的商品、规格、厂家、单位，并保留客户条件和排除条件。

启用前需在飞书开发者后台“事件与回调”配置长连接接收回调，并添加`card.action.trigger`（卡片回传交互），按后台提示使配置生效。代码已注册SDK回调；不需要公网回调地址。图表和展开明细不依赖这个事件配置。应用后台配置和真实客户端点击尚需在手动启动后验收，旧卡不会自动获得按钮。

按钮通过服务端密钥签名，绑定应用、租户、群、提问者和原任务；仅本人最新成功送达结果卡、30分钟内、同快照及语义版本有效。还核对点击消息与发送回执，其他群成员、转发卡、旧卡、未完成／未知送达、清除上下文及第5轮结束后的动作不会执行。相同按钮重复点击只入队一次；动作先持久化、后台执行、发送前复核授权，新卡计入会话轮次。具体计划与商品编码保存在服务端，不信任客户端传入的计划，不发送给模型。任务复用独立助手库JSON字段，无需迁移表结构。

组件协议见飞书官方[按钮](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/interactive-components/button)及[处理卡片回调](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/handle-card-callbacks)。

卡片受容量限制时，比较明细尽量按基准、单位和方向轮流取样，明确提示节选；概览始终保留完整范围统计。极端组合超限时保留概览与核心字段，并说明详细数据需单独询问该主题或在网页查看。不会因明细未展示而改变汇总，缺失值、零基数和不可比情况不会填成零。

离线近似预览：先执行`uv run python scripts/preview_feishu_display.py`，首次执行`node scripts/check_feishu_display.cjs --fetch-chart --business`下载固定公开VChart脚本，之后去掉`--fetch-chart`。`--business`只检查五主题、分单位数量和组合结果共7组桌面／手机布局。按钮为合成布局，回调逻辑由后端合成测试验证；最终显示与点击仍以真实飞书客户端为准。

展示模块见[架构规划](erp-ai-assistant-plan.md)。新增分析能力时，先定义可信的结果字段，再扩展模板；无法支持的业务问题仍会澄清，不会仅为了生成卡片而猜数据。

原生组件依据飞书官方[卡片2.0结构](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/card-json-v2-structure)、[表格](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/card-json-v2-components/content-components/table)、[图表](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/card-json-v2-components/content-components/chart)和[折叠面板](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/card-json-v2-components/containers/collapsible-panel)规范；表格只允许根级放置，不能放进折叠区。

## 首次初始化与运行

先完成[应用接入与授权](feishu-app-setup.md)。已有运行进程无需重复初始化或启动；新环境从根目录执行：

```powershell
uv run python scripts/init_assistant_db.py
uv run python scripts/start_feishu_bot.py --sales --report-path .local/reports/platform-operating-20260916.json
```

初始化只创建独立`ERP_AI_Assistant`及任务表，不修改`ERP_Local`。运行时不自动建库；`ERP_ASSISTANT_ODBC`也必须指向助手库。发现、连接测试和销售问数共用单进程锁，切换前先停止本应用原进程。需要电脑、SQL Server、网络和机器人进程持续运行，尚未配置Windows服务或开机启动。

## 配置、降级与恢复

统一使用根目录`.env`中的`FEISHU_*`、`ERP_AI_*`及数据库／路径配置，参照根目录`.env.example`。默认不再读取`.local/feishu-app.json`。模型仅接收当前问题、消息日期、业务语义配置、结构化会话状态及服务端裁剪的能力／完整日期元信息，不接收ERP记录、结果、名称目录、群／用户身份或原始对话历史。纯数字选择在应用层绑定动作，内部签名选项不交模型推断展示编号。

模型调用前持久化 `analysis_planning` 并移除原问题；完成后，销售计划保存在`analysis`，引导的完整`DialogueTurn`及语义上下文保存在`semantic_notice`，结果／回复先落库再发送。重启可以恢复已保存的引导，无需再次调用模型；引导保存失败不能发送尚未持久化的决策。不确定的模型调用和发送不自动重试。共享对话服务、HTTP四种正常状态、签名动作及409失效语义见[网页与接口说明](analysis-assistant.md#开发接口与验证)；飞书使用同一个服务函数，不经网页HTTP令牌来标识用户。

模型只读取白名单：优先`ERP_AI_BASE_URL`、`ERP_AI_MODEL`、`ERP_AI_API_KEY`；缺项时兼容已有`MAIN_VITE_PI_NORMALIZER_BASE_URL`、`MAIN_VITE_PI_NORMALIZER_MODEL`、`DASHSCOPE_API_KEY`。环境变量优先于根目录`.env`，`ERP_AI_ENABLED=false`可关闭。变更模型配置、应用凭据、租户或快照路径后重启。群／用户授权在接收、分析和发送前重读，撤销后阻止继续处理。

模型可能误解自然语言，供应商也可能超时或暂不可用。卡片中的实际条件供用户核对；云端理解准确性和响应时间需要持续评估，不能以结构化输出校验通过代替业务理解正确。

固定日期指令不调用模型，模型不可用时仍可发：

```text
2026-09-01至2026-09-05 销售概览
2026-09-01至2026-09-05 每日销售趋势
2026-09-01至2026-09-05 商品销售额排行 前10
```

旧版排队任务保持兼容；新版六类功能通过 `analysis_planner` 分支运行。源ERP库保持只读；任务、结果与上下文复用独立 `ERP_AI_Assistant.erp_ai.feishu_sales_jobs`，不新增会话表。

事件只入队，后台Worker解释和计算；消息／事件唯一约束防重复，同用户正在处理时提示等待。分析租约120秒，过期可重新领取，旧租约不能覆盖结果。已保存的结构化计划可恢复本地计算；重启遇到`analysis_planning`或历史`interpreting`时提示重新提问，避免不确定模型调用重复计费。

`ready`表示结果已保存，调用飞书前标为`sending`，收到成功确认后为`sent`。明确业务拒绝为`rejected`，记录数字错误码；网络中断或未知回执为`unknown`。重启遗留`sending`也转为`unknown`：先核对群内消息，再发送新问题，不能批量重置或盲目重发。查询编号、原计划、完整结果和证据保留在助手库；日志／事务备份保留期及自动清理仍需后续运维建设。

## 验证

默认单元及API测试不调用模型或飞书。以下显式测试从 `backend/` 执行：

```powershell
$env:ERP_RUN_ASSISTANT_TESTS='1'
uv run python -m pytest tests/integration/test_feishu_jobs.py -q
Remove-Item Env:ERP_RUN_ASSISTANT_TESTS
$env:ERP_RUN_MODEL_TESTS='1'
uv run python -m pytest tests/integration/test_feishu_analytics_model.py -q
Remove-Item Env:ERP_RUN_MODEL_TESTS
```

SQL测试仅操作随机应用ID下的合成助手任务并清理自身记录；真实模型评测使用合成问题／快照，卡片在本地捕获，不向群发送。运行状态与实际送达应分别记录，不能把这些测试称为群内已收到结果。

最近功能版本的执行结果见 [验证记录](validation.md)。

可复用的合成布局检查，从根目录执行：

```powershell
uv run python scripts/preview_feishu_display.py
node scripts/check_feishu_display.cjs --fetch-chart
```

首次显式下载固定版本VChart公开脚本至`.local/`；之后去掉`--fetch-chart`可离线复查。需要已安装前端依赖和Chrome，或通过`PLAYWRIGHT_CHANNEL`指定已安装浏览器。生成20组样例及40张桌面／手机截图，检查图表渲染、翻页、折叠和页面溢出；表格／容器为近似预览，实际视觉仍以飞书客户端为准。输出仅含合成数据，保存在`.local/feishu-display/`。
